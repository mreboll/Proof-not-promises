# Decision log

| # | Decision | Rejected alternative | Why |
|---|---|---|---|
| D1 | Risk is decided by static rules | Letting an LLM decide | Auditable and reproducible: the same diff always gets the same risk |
| D2 | **Generation** invariance (generated code + diagnostics) | Comparing serialized bytes at run time | All 4 PRs touch only the source generator and the analyzer |
| D3 | Base and PR in separate worktrees and processes | Loading both versions in one process | Avoids assembly-loading conflicts in .NET |
| D4 | The change test is written by an agent that sees only the issue | Having the agent that wrote the fix write it | An agent that validates itself provides no evidence |
| D5 | A test only counts if it fails against a mutant | Accepting any passing test | Rules out empty tests such as `Assert.True(true)` |
| D6 | Gemini at temperature 0 with an on-disk cache | Uncached calls | A repeatable demo, protected against 429s |
| D7 | Prosecutor on **Nemotron**; Defender and tests on **Gemini** | The same model in both roles | If prosecution and defence share a model, they share blind spots; diversity reduces correlated errors |
| D8 | AI-generated tests run in **network-less Modal Sandboxes** | Running them on a laptop | They are untrusted code: isolating them is consistent with the thesis, and it also lets base, PR and mutants run in parallel |
| D9 | CI that records every build (planned on **CRACI**) | No CI | We apply the same rule to our own dependencies. No CRACI runner was available during the event, so the CI runs on `ubuntu-latest`: unit tests without keys plus the pipeline on recorded fixtures |
| D10 | The `Resources/**.g.cs` snapshots skip the scope LLM: they are IN if the issue talks about the generated code | Asking the LLM file by file | In #2297 they are 222 of 237 files: almost all the token cost, for a decision a rule makes just as well |
| D11 | Line rules (`public`, `Span<`, `unsafe`) only look at `src/**/*.cs`, ignoring comments and string literals | Searching every line of the diff | Otherwise the tests' `public async Task` and the text the `.tt` templates emit would be taken for API changes |
| D12 | Gaps in the matrix fall on the cautious side: no evidence → red (M3); high risk without cross-examination → red (M7) | Approving by default when a stage is missing | The thesis is "no proof, no approval": a stage that did not run cannot count as passed |
| D13 | Scope is judged against the literal text of `issues/<id>.md`, delimited as untrusted data | Using the summary in `config.py` | The #2283 summary was wrong (lessons log H1), and the issue or diff text could contain instructions for the model |
| D14 | If the scope LLM returns invalid JSON: retry with the `pro` role and, if it fails again, the file is OUT with "human review" | Aborting the triage, or marking it IN by default | A model failure cannot bring down 237 files, nor silently approve a file nobody classified |
| D15 | Speed: with Modal, triage, change test and invariance run at the same time; triage classifies files in parallel; in the cross-examination, the Defender's first round asks for K variants at once **only with spare LLM capacity** (active objections × (1 + K) ≤ limit; with 36 objections, K = 1) and, with K > 1, a single feedback round remains. The best attempt across all rounds is reported | Raising the limits, or always 3 rounds in series | The capacity sweep showed concurrency no longer limits (39 s of waiting in 17 min); time is set by the chain of long Gemini calls. Variants shorten that chain without asking more than the provider can take, and a red on the PR (a possible defect) is not hidden by a worse later round. Locally nothing changes: the `.work/` worktrees cannot take concurrent runs |
| D16 | Backup requests (*hedging*) to the LLM: if a call takes more than twice its model's median (between 45 and 240 s) and there is spare capacity, an identical call is sent and the first valid answer wins. **Off by default** (`LEDGER_HEDGE=1`): across four real runs its effect could not be separated from Gemini's latency noise | Lowering the 300 s timeout, or accepting the tail | In the three real runs measured, the end was set by ONE straggling Defender call: in #2297, 90 % of the answers had arrived by 396 s and the last one arrived at 1006 s. A lower timeout would also cut legitimate 200–275 s calls; hedging only costs tokens on stragglers |
| D17 | Trust per area (directory, three levels deep), earned with 5 clean signed changes and withdrawn by one escape; in a withdrawn area, green turns yellow (TR). Human spot-checks of a deterministic sample of green files (20 % / 5 %, between 1 and 3 per area). Track record versioned in `trust/track_record.json`, written only by people through the CLI | Areas or levels decided by a model; a random sample; no track record | The challenge asks for trust earned per area from track record, withdrawn after escapes, with humans spot-checking the reviewer. A fixed rule and a hash-based sample are auditable and recomputable. The cap of 3 per area keeps 222 snapshots from becoming 45 reads. Seeded only with the real #2283 escape |
| D18 | Static security rules for a deserializer: R-HIGH-04 (lines with `Type.GetType`, `Assembly.Load`, `Activator.CreateInstance`, `MessagePackSecurity`, `BinaryFormatter`, `Process.Start`, cryptography, `Marshal`) and R-HIGH-05 (`*Security*` / `*Typeless*` paths under `src/`) | Asking an LLM to spot sensitive code | Auditable, deterministic rules, like D1. Resolving types by name is the classic attack vector of "typeless" formatters. None of the 4 PRs triggers them: checked before and after, no risk changes |
